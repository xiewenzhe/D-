# 问题二基线审计与问题三实现框架

审计对象：`q1andq2-another_think/results/q2/selected/schedule.json`，对应 `multi_balanced_seed41`。本报告把“题目约束下的可行性”和“最优性”分开判断。结论是：**该问题二方案可作为问题三的运输调度起点；它是经过交叉复核的可行解，不是已证明的全局最优解，也不是已满足通信约束的问题三解。**仓库根目录 `results/q2/` 中的历史方案不是本次基线。

## 1. 题意与模型口径

- 题目要求 80 个不可拆货箱全部且仅一次交付；每架次从 O01 出发，访问一个或多个服务区后返回 O01。医疗物资的期望时间和标记为首批保障货箱的截止时间是硬约束，其余期望时间计入及时性指标。
- 代码从附件读取 16 个节点、80 个货箱、8 架实体运输机（A4/B2/C2）和 14 组共享电池（A6/B4/C4）。货箱标记、质量、体积、时限和优先级与附件逐箱清单一致；三份问题二相关 Excel 与仓库根目录附件的 SHA-256 完全一致。
- 路线按每个航段的 DEM 最高像元 +50 m 定巡航海拔；O01 在地面海拔作业，服务区在地面 +30 m 作业。时间含准备、逐箱装载、逐段爬升/巡航/下降、每站交接和逐箱交接增量；能耗按各段剩余载荷递减累计。水平能耗采用 `Euse*d/L(q)`，爬升附加能耗采用 `(机体质量+当前载荷)*g*h/(3.6e6*效率)`；下降不另加能耗。这是两套现有实现共同采用的能耗具体化口径，应在论文中明说。
- 每架次总能耗不超过可用电量的 80%；每组电池在再次使用前按题给 90% 分段充电函数充至 100%。无人机从准备开始至返回期间独占，电池从准备开始至返回并完成充电期间独占。

## 2. 代码和结果复核

`src/q2.py` 生成 3988 条候选路线（其中 2205 条多点路线），从中用 CP-SAT 选择恰好覆盖每个货箱一次的路线、整数秒开始时刻，并以 `AddCumulative` 限制每机型实体机和电池数量。飞行时长向上取整，电池占用取 `ceil(飞行时长+充电时长)`，硬时限以逐箱交付偏移向上取整后施加，因此整数调度比导出的连续时间回放略保守。求解后给实体机和电池着色编号。候选池是有限的随机启发式集合，最多 3 个不同服务区；CP-SAT 的下界仅限此候选池和整数秒模型。

使用 `code/audit_q2_baseline.py`，以**另一套 GeoTIFF 地形/物理代码**独立回放全部 3988 条候选和选中方案；另调用原项目 `src/validate.py::validate_q2` 回放选中方案。两种审计均通过：

|---|---:|
| 货箱覆盖 | 80/80，每箱恰好一次 |
| 选中架次/多点架次/航段 | 24 / 2 / 50 |
| 硬时限违反/期望迟到货箱 | 0 / 0 |
| 实体机/电池使用 | 8 架 / 14 组，26 次同资源相邻任务转接均无重叠；最小真实间隙分别为 0.169 s / 0.664 s |

原始 `selected/schedule.json` 和 `multi_balanced_seed41/schedule.json` 字节完全相同；`selected/summary.json` 也相同。逐箱、架次、电池、航段四张 CSV 与选中 JSON 的编号、时间、路线和巡航高度一致。原项目独立回放返回 `passed=True`、80 箱、24 架次、0 能量违反、0 资源冲突。

模型内的整数秒目标为 `100×整数完工时刻 + Σ优先级×(整数交付时刻+100×整数迟到秒数) + Σ(10×四舍五入的 Wh + 10000)`。原求解器状态为 `FEASIBLE`，不是 `OPTIMAL`；报告的候选池内相对界差约 54.45%，因此不能把 24 架次或 69.58 kWh 宣称为全局最优。不同权重的实验行也不能直接按各自目标值大小比较，只能比较共同的实物指标和可行性。

## 3. 复现边界与后续使用条件

原项目 `.venv/pyvenv.cfg` 的解释器仍指向 `D:\py\Python3`，本机没有该解释器；当前仓库 `.venv` 也没有 `ortools` 和 `pytest`。因此本次没有重跑完整 CP-SAT 搜索或原有 pytest 套件；已对存档求解结果作独立物理复算、整数目标重建及原验证器回放。此限制影响“重新求解得到同一解”的复现，不影响现有方案的约束可行性结论。若论文声称优化水平，应写为“在有限候选池中找到的可行解”，并给出权重和求解时限。

问题三应直接读取上述选中 JSON 与候选池，保留输入哈希、Q2 方案哈希及来源名。问题三任何路线、开始时刻或电池/实体机变更，都必须再次执行问题二全套约束验证。两条多点路线 `Q2-009: S009→S012`、`Q2-016: S011→S014` 在问题四中还会形成服务区同组约束。

## 4. 问题三的联合模型

首先把每条运输航段展开为爬升、水平巡航、下降，服务区停留展开为交接阶段，得到分段仿射三维轨迹 `p_r(t)`。准备和装载时间只决定起飞时刻，题目要求通信持续的区间从起飞持续至最后返航，含每次交接。固定网关端点为 O01 地面海拔 +20 m。

对每个时刻和运输机，必须满足下式之一：双向运输机—网关直连可用；或存在一架已建链且正在悬停服务的中继机，使**同一时刻**运输机—中继接入链路与中继—网关回传链路均可用。链路按 2400 MHz 的三维距离、DEM 遮挡、附加损耗及两个方向中较小的允许损耗判定。不预设“一架中继只能服务一架运输机”，因为附件没有给出并发扇出限制；但每架运输机同一时刻只选一个服务提供者。

中继候选由 DEM 内的经纬度和 0–300 m 离地高度组成。每次中继任务有 180 s 准备、出航三阶段、30 s 建链、悬停服务、回航三阶段、300 s 同机周转。能耗为往返巡航和爬升能耗，加 `(1.05+0.05) kW × (建链+服务秒数)/3600`；返航 SOC 不低于 20%。两架中继实体机与六个共享能源组件分别作为独立资源，组件再次使用前按题给分段曲线充满。联合完工时间取**运输和中继全部返航**的最晚时刻。

求解目标先保证所有硬时限、能源和连续通信约束；然后报告按优先级加权的迟到、联合完工时间、运输+中继总能耗、两类架次数及 Pareto/权重敏感性，避免只给单一主观权重的一个数。

## 5. 求解与验证流程

1. **固定 Q2 基线筛查。**按上述轨迹对直连做分段端点和细时间网格预检，形成直连失效时间窗；预检只用于生成候选，不作为连续覆盖证明。本次 20 s 预检得到 1863 个位置样本、742 个直连失效样本、20/24 个架次受影响，某些时刻同时有 6 架运输机直连失效。这说明需要考虑中继共享、空间覆盖和时段匹配，不能由“6 架失联”推断需要 6 架中继。
2. **中继候选与服务窗口。**对 DEM 网格、服务区、航段附近和山脊可见位置进行分层候选搜索；筛去回传不可用、航程不足或悬停高度越界的点。计算每个候选位置对各运输轨迹失联窗口的接入覆盖，以及可用服务时长上界。优先使用较少候选求解，再在未覆盖的窗口附近自适应加点。
3. **联合调度。**先尝试保留 Q2 组批和时间表，仅排中继；若不成立，放开运输架次的开始时刻、实体机/电池重新分配；仍不成立时，利用已审计候选池替换组批、访问顺序和机型。用可选区间/累积约束限制 8 架运输机、14 组电池、2 架中继机、6 个组件；对失联窗口施加服务时段和两段链路同步覆盖。关键硬时限余量只有 220.525 s，且已有无人机/电池的保守预留转接间隙为 0 s（真实最小间隙仅 0.169 s / 0.664 s），重排时要显式保留资源余量并允许提前部署中继。
4. **全量验证。**独立回放每箱交付、每段载荷/能耗、运输与中继 SOC、充电、实体设备和能源组件占用、联合完工时刻。通信先做细采样排错，再用 DEM 像元与分段仿射轨迹的保守区间界证明每个时间小区间至少有一条有效链路；遇到不能证明的区间标记为 `UNKNOWN` 并继续细分或修改方案，不能把采样无失联直接写成“连续通信成立”。输出逐架次的直连/中继保障时间区间及最小链路余量。
5. **为问题四保留关系。**保存每条运输路线覆盖的服务区、每个中继任务保障的运输架次和时间窗、对应实体机与能源组件。固定问题三方案分区时，多点运输架次及跨服务区中继保障关系可直接转成同组约束与组内资源需求。

建议输出：`q3/transport_schedule.json`、`q3/relay_missions.json`、`q3/communication_intervals.csv`、`q3/resource_ledger.csv`、`q3/validation.json` 与共同输入/源码/结果哈希清单。只有 `validation.json` 中货箱、时限、设备、能量及连续通信检查全部通过，才将其作为问题四的固定输入。

## 7. 后续优化实验（保留原基线）

用户提出进一步优化问题二后，已在工作区 `.venv` 安装与原方案同版的 OR-Tools 9.15.6755；原 `selected` JSON 与 CSV 均未覆盖。新结果位于 `results/q2_improved/`，包括调度 JSON、摘要、四张明细 CSV、搜索历史及固定路线最优性证书。对新结果运行同一独立审计器，全部通过。

| CP-SAT 同权重整数目标 | 4,290,638 | **4,281,382** |
| 优先级加权平均交付时刻 | 2776.663 s | **2766.981 s** |

| 期望迟到箱/硬时限违反 | 0 / 0 | 0 / 0 |

目标改善 **9256（约 0.216%）**，来自相同路线集合的时间表调整。固定这 24 条路线、允许重新安排整数秒开始时刻和同型实体机/共享电池时，CP-SAT 在约 48 s 内返回 `OPTIMAL`，目标上界与下界均为 **4,281,382**。因此改进时间表对该**固定路线子问题**已证明最优；这不证明路线选择全局最优。20 轮路线邻域搜索、完整 3988 候选池的 120 s 求解以及 158 条“原路线 + 两架次合并”候选的 90 s 求解均未再找到更优可行解，但也未证明不存在。

原候选池具有实际缺口：仅对当前 24 架次进行两两合并、检查单路线质量、体积、航程及硬时限，就找到 **125 条合法但原 3988 路线池未收录的路线**。这些路线单独可飞不代表能嵌入完整资源时间表；它们足以证明原池不能用于全局最优性断言。要证明整个问题二全局最优，必须在完整可行路线空间上建模，或采用可证明精确的列生成/分支定价与调度约束，并在相同目标口径下使全局上下界收敛。实际赛题中可优先做自适应增列、强下界和多起点邻域搜索，把新可行解与严格界分开报告。
